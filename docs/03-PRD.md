## 1. 한 문장 정의

**계산대에서 한 발짝도 움직이지 못하는 심야 편의점 알바가, 점장이 남긴 수칙과 손님을 대조해 판정하는 게임. 문제는 수칙 중 일부가 거짓말이라는 것이다.**

---

## 2. 왜 이 게임인가

### 2.1 시장 근거
- 호러 장르 Steam 히트율 3.2%로 상승세 (2D 플랫포머의 약 17배)
- 1~3시간 저가 호러의 연속 성공 (The Exit 8, Buckshot Roulette)
- 규칙 기반 호러(규칙괴담)가 유행 중 → 관객이 문법을 이미 안다

### 2.2 1인 개발 적합성
- **아트가 전부 코드다.** 캐릭터 모델·애니메이션·스프라이트가 0개. 화면 = 셰이더 + 벡터 + 타이포
- 이동이 없으므로 레벨 디자인·내비게이션·물리가 불필요
- 콘텐츠가 **데이터**(수칙 JSON)라 확장 비용이 선형적

### 2.3 차별화 (상세: `00-competitive-analysis.md`)
익숙함: 규칙 대조 판정 + 야간 근무 호러
**새로운 축 단 하나: 수칙이 플레이어를 속인다.** "규칙을 지켰는가"가 아니라 **"어떤 규칙을 믿을 것인가"**가 게임의 질문이 된다.

---

## 3. 코어 게임플레이

### 3.1 화면 구성 (고정, 전환 없음)
플레이어는 계산대 뒤에 고정된다. 화면에 동시에 존재하는 네 영역:

1. **POS 단말** — 상품 스캔, 결제, 신분 확인. 조작의 중심.
2. **CCTV 4분할 모니터** — 매장 내부. 증거 수집용. *(FNAF와 달리 위협을 막는 도구가 아니다)*
3. **창문** — 밖의 실루엣. 손님이 오기 전 예고.
4. **수칙 클립보드** — 점장이 남긴 규칙 목록. 밤마다 갱신된다.

### 3.2 코어 루프 (1 사이클 ≈ 40~90초)
```
창밖 실루엣 등장  →  문 종소리  →  손님이 카운터로
        ↓
CCTV·POS·손님 외형에서 단서 수집
        ↓
수칙 클립보드와 대조
        ↓
판정: 정상 응대 / 거부 / 특수 대응
        ↓
결과 (즉시 또는 지연 피드백)  →  다음 손님
```

### 3.3 밤 구조
- 1박 = 22:00 ~ 06:00, 실제 시간 **8~12분**
- 손님 8~14명. 그중 이상 개체 2~5명
- 밤 종료 시 정산 화면 → 다음 밤 수칙 갱신

### 3.4 진행과 긴장 곡선

| 밤 | 도입되는 것 | 의도 |
|---|---|---|
| 1 | 수칙 3개. 전부 참. 튜토리얼 | 문법 학습 |
| 2 | 수칙 추가. CCTV 단서 필요 | 정보원 확장 |
| 3 | **수칙 간 모순 발생** | 첫 충격 |
| 4 | 손님이 수칙을 언급하며 압박 | 사회적 압력 |
| 5 | **거짓 수칙 확정 등장** | 코어 훅 개화 |
| 6 | 수칙 출처 자체가 의심스러워짐 | 서사 전환 |
| 7 | 최종 선택 → 엔딩 분기 | 결말 |

## 5. 범위 밖 (Non-Goals)

명시적으로 만들지 않는다. 요청이 와도 거절한다.

- 멀티플레이·협동
- 1인칭 이동, 매장 탐험, 3D 전환
- 절차적 무한 생성 (본편은 수작업 7박)
- 콘솔·모바일 이식 (출시 후 별도 판단)
- 분기 서사의 대규모 확장 (엔딩 3종 상한)
- 캐릭터 커스터마이징, 상점, 성장 트리

---

## 6. 기술 제약

- **에셋 파일 금지**: 스프라이트·3D 모델·텍스처·애니메이션 0개. 오디오만 외부 허용
- Godot 4.x, GDScript 정적 타입
- `systems/`는 노드 비의존 → 헤드리스 테스트 가능
- 문자열 전량 외부화 (한/영 동시, 중국어 간체 확장 대비)
- 타깃 사양: 통합 그래픽에서 1080p 60fps
- 실존 브랜드·로고·상품명 사용 금지
