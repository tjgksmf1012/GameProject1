# Icebox — 아이디어 무덤

> **용도**: 개발 중 떠오른 아이디어를 여기 적고 **즉시 잊는다.**
> 마일스톤 종료 시에만 열어보고, 대부분은 그대로 둔다.
>
> 이 파일이 존재하는 이유: 1인 개발 최대 사망 원인은 스코프 크립이고, AI로 개발이 빨라지면 그 위험은 **더 커진다.** 좋은 아이디어를 거절하는 게 아니라 **미루는** 장치다.

---


## 판정 기록

### [2026-08-05] 플레이테스트 판정 로그 (`SessionLog`)

- 어떤 사용자 요구(N번)를 충족? → **없음.** 플레이어용 기능이 아니다
- 아트 에셋 필요? → 아니오
- 없으면 게임이 성립 안 하나? → 게임은 성립한다. 다만 **현재 P0(M0-4 플레이테스트)가 성립하지 않는다**
- 판단: **채택** (F-번호 없음 — 출시 빌드에 들어가지 않는 개발 도구)

M0의 유일한 남은 항목이 5명 플레이테스트인데, 계측이 없으면 산출물이 인상뿐이다.
판정 소요 시간·재시작 횟수·세션 길이는 자동으로 잡을 수 있고, 그게 H1·H4의 방증이 된다.
서버로 아무것도 보내지 않고 `user://`에만 쓴다.

> ⚠ **출시 텔레메트리(F-11)와 혼동하지 말 것.** F-11은 여전히 `Could`이고 데모 이후다.
> M1 착수 시 이 로그가 게임 코드에 남아 있으면 안 된다 — 필요 없어지는 순간 지운다.

## 마일스톤 종료 시 검토 절차

1. 대기 목록을 처음부터 읽는다
2. 각 항목에 대해 물어본다: **"이걸 넣으려고 출시를 한 달 미룰 수 있나?"**
3. 대부분의 답은 "아니오"다. 그러면 그대로 둔다
4. "예"인 항목만 `04-functional-spec.md`에 F-번호를 받고 올라간다
