# 05. 기능 우선순위

> Claude Code는 **매 세션 시작 시 이 문서에서 다음 P0를 확인**한다.
> 원칙: 1인 개발에서 우선순위 판단 실수는 곧 프로젝트 사망이다. 애매하면 **자른다.**

---

## 1. 판단 기준

기능마다 아래 3개를 답한다. 하나라도 막히면 후순위 또는 폐기.

1. **어떤 사용자 요구를 충족하는가?** (`02-user-needs.md`의 N1~N10 중 하나 이상)
2. **이게 없으면 데모가 성립하는가?** — 성립하면 데모 범위 밖
3. **아트 에셋이 필요한가?** — 필요하면 **재설계 또는 폐기** (`CLAUDE.md` 1.1)

## 3. 마일스톤별 P0 (순서대로 진행)

### M0 — 프로토타입 (2026.08)
목표: **H1·H2를 죽이거나 살린다.** 예쁠 필요 전혀 없다.
1. ☑ `RuleEngine` 최소 구현 (참 2개 / 거짓 2개)
2. ☑ 손님 6명 → 판정 → 결과, 텍스트만으로. 밤 하나 완주 가능
3. ☑ 거짓 수칙 2개 삽입 (하나는 판매 유도, 하나는 거부 유도)
4. ☐ **5명 플레이테스트** → H1(거짓 수칙 재미?), H2(고정 시점 답답?) 검증

> 공정성 불변식 4개(F-01)는 `tests/test_fairness.gd`로 자동 검증 중이다.
> `godot --headless --script res://tests/run_tests.gd` — 현재 422개 검사 통과.
> 손으로 플레이하기 전에 `tools/playthrough.gd`로 밤 전체 대본을 찍어볼 수 있다.

**플레이테스트 시 반드시 두 조건을 모두 측정할 것**: `data/balance.json`의
`grace_on_first_trap`을 켜고 한 번, 끄고 한 번. 첫 함정에서 죽이느냐 봐주느냐가
H1의 성패를 가를 가능성이 높다 — 문법을 배우기 전에 죽으면 학습이 아니라 배신으로 읽힌다.

> ⚠ **여기서 H1이 죽으면 아래 전부 폐기하고 컨셉을 다시 짠다.** 예쁘게 만들고 나서 검증하면 되돌릴 수 없다.

### M3 — 데모 (2026.12~2027.01)
1. ☑ 밤 3 완성 — **전환(decaying)**: 어제 맞던 둘째 수칙이 오늘 틀린다
2. ☑ 사망 연출 3종 (수칙 · CCTV · 접근 — 무엇이 죽였는지로 고른다)
3. ☑ F-10 한/영 현지화 — `--locale=en`, 로케일 키 일치를 테스트가 강제

> **밤 3 솔버 결과** (`tools/solver_audit.gd`, 손님 9명)
> 클립보드를 전부 믿는 플레이어 6/9 — **오판 3회 = 한계치, 이 밤을 넘기지 못한다.**
> 모순된 수칙을 전부 버리는 플레이어 5/9, 예외 조항을 우선하는 플레이어 8/9.
> 밤 2와 처벌 대상이 바뀌었다. 밤 2는 오독을 때렸고, 밤 3은 **맹신**을 때린다.

> ⚠ **PRD 3.4의 밤별 곡선과 실제 구현이 어긋나 있다.** PRD는 밤 3에서 수칙 모순이
> 처음 나오고 거짓 수칙은 밤 5부터라고 했지만, M0가 H1을 즉시 검증하려고 밤 1에
> 전부 배치했다. 밤 4~7을 설계할 때 곡선을 다시 잡을 것.

> ☑ **빚 갚음 — 점장 필체로 쓴 거짓 수칙 (밤 4).**
> 밤 3까지는 "점장이 쓴 줄은 그냥 믿는다"가 100% 통하는 지름길이었다. 밤 4의 아홉
> ("얼굴을 가린 것은 부끄러워서이니…")이 그걸 끝낸다. 점장 필체 참2/거짓1, 남의 필체
> 참2/거짓4 — 이제 종이는 어느 쪽으로도 답을 주지 않는다.
> 불변식 2d가 이 밤에 **실제로 깨어났다** (잠자는 검사 표시가 사라졌다).
>
> 종이가 빠진 자리는 두 단서가 메운다: 수칙 간 모순, 그리고 문체 규약("점장은 이유를
> 대지 않는다"). 후자는 사람이 지키기로 한 규약이었는데, 하중 구조물이 된 이상
> `tests/test_rule_voice.gd`가 **두 로케일 모두에서** 기계로 지킨다 — 번역자가
> 「부끄러워서이니」를 매끄럽게 다듬어 없애면 그 로케일에서 코어 훅이 죽기 때문이다.

> **밤 4 솔버 결과** (손님 10명) — 세 가지 오독이 전부 오판 한계를 넘긴다.
> 클립보드를 전부 믿는 플레이어 6/10, 모순된 수칙을 전부 버리는 플레이어 4/10,
> 나중 수칙이 앞을 덮는다고 보는 플레이어 6/10. 참 수칙만으로 추론하면 10/10이다.
> **인내 타이머는 판정에 손대지 않는다.** 시간이 다하면 대신 판정하거나 오판으로 세는
> 설계를 검토하고 버렸다 — 수칙 일곱 줄을 읽고 CCTV와 대조해야 하는 게임에서 타이머로
> 죽이면 **꼼꼼히 읽는 행동이 처벌받는다.** 대신 긴장도가 오르고 손님이 재촉한다.
> 그리고 **모든 손님이 똑같은 속도로 재촉한다** — 이상 손님만 다르게 굴면 플레이어는
> 관찰 대신 기다리기로 풀고, 그 순간 CCTV도 클립보드도 필요 없어진다.
> `tests/test_patience.gd`가 이 두 가지를 손님 22명 전원에 대해 감시한다.

4. ☑ 제목 화면 — **튜토리얼 대신 두 줄로 가르친다** (M2 게이트의 전제)
5. ☐ 데모 빌드 + Steam 페이지 오픈
6. ☐ 트레일러 (첫 5초에 훅)

> **제목 화면이 하는 일은 튜토리얼이다.** 이 게임은 설명 화면이 없고, 앞으로도 만들지
> 않는다. 대신 첫 화면이 두 줄로 가르친다 — 「점장이 남긴 수칙대로 손님을 받으시오」로
> 무엇을 하는 게임인지, 한 박자 뒤에 뜨는 「수칙 전부가 참인 것은 아니다」로 왜 어려운지.
> 버튼을 두지 않은 것도 같은 이유다. 부스에서 마우스를 어디로 옮길지 고민하는 몇 초가
> 30초 예산에서 나간다. `--booth`는 세이브를 무시하고 항상 첫 밤부터 시작한다 —
> 시연대에 앞사람의 3일째 밤이 남아 있으면 다음 사람은 이 게임을 이해할 수 없다.

## 4. 컷 라인 (일정이 밀리면 이 순서로 자른다)

밀렸을 때 **당황해서 아무거나 자르지 않기 위해** 미리 정해둔다.

1. 도전과제
2. 엔딩 분기 → 단일 엔딩
3. 무작위화 → 고정 순서
4. 중국어 간체 → 출시 후 패치
5. 본편 7박 → **5박** (분량보다 완성도)
6. 사망 연출 3종 → 2종

**절대 자르지 않는 것**: 공정성 불변식(F-01), 3초 리플레이(F-07), 셰이더 세트(F-09).
이 셋을 자르면 게임이 "싸구려"가 되고, 그 순간 아무도 돈을 내지 않는다.
