# 02. 사용자 요구 분석

> 목적: "누가, 왜, 어떤 상황에서 이 게임을 켜는가"를 확정하고, 그것을 **설계 요구사항으로 번역**한다.
> 근거: `01-user-research.md`. 이 문서의 상당 부분은 아직 **가설**이다.

---

## 1. 타깃 세그먼트

우선순위가 곧 의사결정 순서다. 충돌하면 **P1이 이긴다.**

### P1. 호러 인디 상시 소비자 (핵심)
- 짧은 호러 인디를 월 2~4개씩 소비. Steam 할인·신작 큐를 습관적으로 훑는다.
- 구매 결정 시간이 짧고, 가격 저항이 낮다 ($10 이하).
- **켜는 이유**: 오늘 밤 한 시간을 채울 새롭고 무서운 것.
- **이탈 이유**: 시작 5분 안에 신선한 게 안 나오면 환불.

### P2. 스트리머 / 콘텐츠 크리에이터 (발견성 엔진)
- 시청자 반응이 나올 소재를 찾는다. 이들이 이 게임의 **유일한 현실적 마케팅 채널**이다.
- **켜는 이유**: 방송 소재. 시청자가 같이 풀 수 있고, 실패가 그림이 되는 게임.
- **이탈 이유**: 초반이 지루하거나, 설명이 길거나, 클립이 안 나온다.

### P3. 시스템·퍼즐 애호가 (리텐션)
- Papers, Please·Return of the Obra Dinn 계열을 좋아한다. 규칙을 해부하는 데서 쾌감을 얻는다.
- **켜는 이유**: 추론할 만한 구조가 있다.
- **이탈 이유**: 규칙이 실은 랜덤이었다는 걸 깨닫는 순간. → **공정성이 생명이다.**

### P4. 행사 관람객 (지스타·BIC 부스)
- 시끄럽고 밝은 환경에서 **5분 이내**로 판단한다. 헤드폰이 없을 수도 있다.
- **켜는 이유**: 화면이 눈에 띄어서.
- **이탈 이유**: 30초 안에 뭘 하는 게임인지 모르면 떠난다.

### 명시적 비대상
호러 기피층, 장편 서사 RPG 소비자, 모바일 캐주얼, 협동 플레이 목적 유저. **이들을 잡으려는 기능 요청은 전부 거절한다.**

## 3. 요구 → 설계 번역표

| # | 사용자 요구 | 세그먼트 | 설계 요구사항 | 검증 기준 |
|---|---|---|---|---|
| N1 | 뭘 하는 게임인지 즉시 알고 싶다 | P4, P2 | 튜토리얼 없이 **첫 30초 안에** 코어 루프가 자명해야 함. POS·수칙·손님이 첫 화면에 동시에 보임 | 신규 테스터 5명 중 4명이 설명 없이 첫 판정 성공 |
| N2 | 짧게 끊어 하고 싶다 | P1, P2 | **1박 = 8~12분**, 밤 단위 자동 저장, 중간 종료 가능 | 세션 로그 중앙값 8~12분 |
| N3 | 실패가 억울하지 않아야 한다 | P3 | 모든 실패는 **사후 재구성 가능**해야 함. 사망 시 "무엇을 놓쳤는지" 3초 리플레이 제시 | "운이었다"는 리뷰 5% 미만 |
| N4 | 방송에서 시청자와 같이 풀고 싶다 | P2 | 정보가 **화면에 전부 보인다**. 숨겨진 스탯·주사위 없음. 시청자도 추론 가능 | 실황 영상에서 채팅이 정답을 외치는 장면 발생 |
| N5 | 실패가 웃겨야 한다 | P2 | 사망 연출은 공포 + **약간의 부조리**. 반복 시청해도 견딜 것 | 클립화되는 사망 연출 3종 이상 |
| N6 | 새로운 걸 보고 싶다 | P1 | 매 밤 **최소 1개의 새 수칙 또는 새 규칙 유형** 도입 | 밤별 신규 요소 체크리스트 100% |
| N7 | 스포일러를 봐도 다시 할 만해야 한다 | P1, P3 | 수칙 조합·손님 순서 **부분 무작위화**. 정답 암기만으로 클리어 불가 | 2회차 플레이 시간 1회차의 60% 이상 |
| N8 | 싸구려로 보이지 않아야 한다 | 전체 | 모든 인터랙션에 트윈·사운드·셰이더 반응. 정적인 화면 금지 | 스크린샷 반응 테스트 통과 |
| N9 | 소리 없이도 플레이 가능해야 한다 | P4 | 오디오 단서에 **반드시 시각 대체 단서** 병기 (부스는 시끄럽다) | 음소거 상태로 클리어 가능 |
| N10 | 내 언어로 하고 싶다 | 전체 | 한국어·영어 동시 지원, 중국어 간체 출시 시 추가. 문자열 전부 외부화 | 하드코딩 문자열 0개 |

## 4. 요구 간 충돌과 결정

**충돌 A: N7(재플레이) ↔ N3(공정성)**
무작위화를 강하게 하면 실패가 운처럼 느껴진다.
→ **결정**: 무작위화는 **수칙 조합과 손님 순서**에만 적용. 개별 판정의 정답은 항상 화면 정보만으로 결정 가능하게 한다. 즉 "무엇이 나올지"는 랜덤이되 "어떻게 판단할지"는 결정론적.

**충돌 B: N1(즉시 이해) ↔ N6(계속 새로움)**
새 규칙이 매번 나오면 첫 30초 이해가 어려워진다.
→ **결정**: 1박은 **단 하나의 규칙만** 가르치는 튜토리얼로 설계. 복잡도는 2박부터 증가.

**충돌 C: N5(웃긴 실패) ↔ 호러 톤**
→ **결정**: 부조리는 **사망 후 연출**에만 허용. 플레이 중에는 절대 웃기지 않는다. 긴장 유지가 우선.

**충돌 D: N9(무음 플레이) ↔ 호러의 사운드 의존**
→ **결정**: 오디오는 **긴장 증폭용**, 판정에 필요한 정보는 **항상 시각으로도 제공**. 소리는 보상이지 필수 입력이 아니다.

## 5. 이 문서를 쓰는 법

- 새 기능 아이디어가 나오면 **N1~N10 중 어떤 요구를 충족하는지** 먼저 답한다. 답이 없으면 만들지 않는다.
- 우선순위 판단(`05-prioritization.md`)의 근거는 항상 이 표를 참조한다.
- 플레이테스트 후 요구가 틀렸다고 밝혀지면 **이 문서를 고친다.** 기능 목록이 아니라 요구를 먼저 고쳐야 한다.
