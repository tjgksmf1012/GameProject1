# CLAUDE.md

이 파일은 Claude Code가 매 세션 시작 시 읽는 프로젝트 헌법이다.
**여기 적힌 제약은 협상 대상이 아니다.** 제약을 어겨야 할 것 같으면 코드를 쓰기 전에 나에게 물어라.

---

## 0. 프로젝트 한 줄 요약

한국 심야 편의점에서 점장이 남긴 **수칙**과 손님을 대조해 판정하는 규칙 기반 아날로그 호러.
플레이어는 계산대에서 한 발짝도 움직이지 않는다. 세계는 오직 **POS 단말 · CCTV 4분할 모니터 · 창밖 · 수칙 클립보드** 네 개의 화면으로만 인식된다.

- 코드네임: `NIGHTSHIFT`
- 엔진: **Godot 4.x / GDScript**
- 타깃: **Steam (Windows 우선, Proton 호환 유지)**
- 개발: 1인 + Claude Code

---

## 1. 절대 규칙 (위반 금지)

### 1.1 아트는 전부 코드다
이 프로젝트에는 **스프라이트 시트, 픽셀 아트, 3D 모델, 손그림 텍스처, 캐릭터 애니메이션이 존재하지 않는다.**
화면에 보이는 모든 것은 아래 중 하나로만 만든다:

- Godot `Control` 노드 + 테마 (UI, POS, 클립보드)
- `Polygon2D` / `Line2D` / 절차적 도형 (실루엣, 집기)
- **셰이더** (CRT 곡률, 스캔라인, 그레인, 색수차, 디더링, 팔레트 스왑)
- `GPUParticles2D`
- 타이포그래피 (폰트가 아트의 절반이다)

> 에셋 파일을 새로 요구하는 설계안은 반려한다. "이건 이미지가 필요합니다"라는 말이 나오면 **코드로 만들 방법**을 먼저 제안하라.

**허용되는 외부 에셋은 오디오뿐이다.** (CC0 / 라이선스 확인 완료분만, `credits.md`에 즉시 기록)

### 1.2 씬 파일보다 코드
- `.tscn`은 **얕게** 유지한다. 노드 트리 깊이 4단계 초과 금지.
- 레이아웃·상태·연결은 GDScript로. 에디터에서만 존재하는 설정은 금지 (내가 Claude Code로 못 고친다).
- 씬 간 통신은 **시그널**. 노드 경로 하드코딩(`get_node("../../..")`) 금지.

### 1.3 데이터는 코드 밖에
수칙, 손님, 이벤트, 대사는 **전부 `data/` 하위 JSON 또는 `.tres` 리소스**로 분리한다.
밸런싱을 위해 GDScript를 고치는 일이 생기면 그건 설계 실패다.

### 1.4 파일 크기 상한
- GDScript 파일 **300줄 초과 금지**. 넘으면 분리한다.
- 함수 **40줄 초과 금지**.
- 이유: 코드베이스가 커지면 너의 컨텍스트 밖으로 나가고, 그 순간부터 내가 이해 못 하는 코드가 쌓인다.

### 1.5 내가 이해하지 못하는 코드는 머지하지 않는다
큰 변경 전에는 **먼저 계획을 3~5줄로 설명하고 내 승인을 받아라.** 승인 없이 파일 여러 개를 동시에 갈아엎지 마라.

## 2. 디렉터리 구조

```
res://
├── main/              # 부트스트랩, 씬 전환, 게임 상태 머신
├── systems/           # 순수 로직 (노드 의존 없음, 테스트 가능)
│   ├── rules/         # 수칙 평가 엔진
│   ├── customers/     # 손님 생성·검증
│   └── night/         # 밤 진행, 시간, 스코어
├── ui/                # POS, 클립보드, CCTV, 창문
├── shaders/           # .gdshader 전용
├── audio/             # 외부 에셋 유일 허용 구역
├── data/              # JSON/리소스 — 수칙·손님·이벤트 정의
└── tests/             # GUT 테스트
```

**`systems/`는 Godot 노드를 상속하지 않는다.** 순수 `RefCounted`/`Resource`로 작성해 헤드리스 테스트가 가능하게 한다. 이게 이 프로젝트에서 가장 중요한 아키텍처 결정이다.

## 3. 피드백 루프 (너는 화면을 볼 수 없다)

너는 실행 화면을 보지 못한다. 그러므로:

1. **로직은 테스트로 검증한다.** `systems/` 변경 시 `tests/`에 케이스를 같이 쓴다.
   ```bash
   godot --headless --script res://tests/run_tests.gd
   ```
2. **시각적 변경은 스크린샷으로 검증한다.** `tools/screenshot.gd`가 특정 상태를 렌더해 PNG로 저장한다. 내가 그걸 붙여넣어 준다.
3. 확신이 없으면 **추측해서 진행하지 말고 나에게 화면을 물어봐라.**

## 4. 코딩 컨벤션

- GDScript 공식 스타일 가이드 준수. `snake_case` 함수/변수, `PascalCase` 클래스.
- **정적 타입 필수**: `var hp: int = 3`, `func judge(c: Customer) -> Verdict:`
- `class_name`은 `systems/`와 `data/`에서만 선언.
- 주석은 **왜**를 적는다. 무엇을 하는지는 코드가 말한다.
- 매직 넘버 금지 → `data/balance.json`.
- 한국어 문자열은 전부 `data/strings_ko.json`. 영어는 `strings_en.json`. **하드코딩된 표시 문자열 금지** (출시 시 최소 영어·중국어 간체 필요).

## 5. "주스(juice)"가 이 게임의 그래픽이다

예산이 0인 게임이 유료급으로 보이는 이유는 그림이 아니라 **반응성**이다. 새 인터랙션을 만들 때마다 아래를 기본으로 넣어라:

- 모든 UI 이동/등장에 **트윈 + 이징** (`Tween`, `EASE_OUT`, `TRANS_CUBIC`)
- 판정 순간 **히트스톱** (0.05~0.12초 타임스케일 정지)
- 결정적 순간에 **스크린 셰이크** (감쇠 필수, 과하면 즉시 줄인다)
- CRT/그레인 셰이더는 **항상 켜져 있되 강도가 상황에 따라 변한다** (긴장도 = 셰이더 파라미터)
- 소리 없는 인터랙션 금지. 최소한 UI 클릭음은 붙인다.

> 기능이 "동작한다"는 완료가 아니다. 주스가 붙어야 완료다.

## 6. 지금 하지 말아야 할 것 (스코프 방어)

아래는 **명시적으로 범위 밖**이다. 내가 요청해도 먼저 반대 의견을 말해라:

- 멀티플레이어 / 협동
- 3D 전환, 1인칭 이동
- 절차적 무한 생성 (본편은 수작업 설계 7박)
- 콘솔·모바일 이식
- 세이브 슬롯 다중화 (단일 자동저장이면 충분)
- 도전과제 (출시 직전 마일스톤에서만)

**AI가 빠르다는 이유로 기능을 늘리는 것이 이 프로젝트 최대 사망 원인이다.**
