## 5. 로드맵 운영 규칙

1. **추정 시간은 3배로 잡는다.** 인디 개발자들이 반복해서 하는 조언이고, AI로 빨라져도 통합·디버깅·폴리싱은 안 줄어든다.
2. 마일스톤 종료 시 **실제 소요 기간을 기록**한다. 다음 추정을 보정하기 위해서다.

   | M | 계획 | 실제 | 배수 |
   |---|---|---|---|
   | M0 | 4주 | | |
   | M1 | 8주 | | |
   | M2 | 4주 | | |

3. **게이트를 통과하지 못하면 다음 마일스톤으로 넘어가지 않는다.** 특히 M0의 H1은 절대 건너뛰지 않는다.
4. 일정이 밀리면 기간을 늘리지 말고 **`05-prioritization.md` §4 컷 라인 순서대로 자른다.**
5. 이 문서는 매 마일스톤 종료 시 갱신한다.
