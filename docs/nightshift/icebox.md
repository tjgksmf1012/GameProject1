# Icebox — 아이디어 무덤

> **용도**: 개발 중 떠오른 아이디어를 여기 적고 **즉시 잊는다.**
> 마일스톤 종료 시에만 열어보고, 대부분은 그대로 둔다.
>
> 이 파일이 존재하는 이유: 1인 개발 최대 사망 원인은 스코프 크립이고, AI로 개발이 빨라지면 그 위험은 **더 커진다.** 좋은 아이디어를 거절하는 게 아니라 **미루는** 장치다.

---

## 기록 형식

```
### [YYYY-MM-DD] 아이디어 한 줄
- 어떤 사용자 요구(N번)를 충족? →
- 아트 에셋 필요? →
- 없으면 게임이 성립 안 하나? →
- 판단: 보류 / 채택(F-번호 부여) / 폐기
```

## 마일스톤 종료 시 검토 절차

1. 대기 목록을 처음부터 읽는다
2. 각 항목에 대해 물어본다: **"이걸 넣으려고 출시를 한 달 미룰 수 있나?"**
3. 대부분의 답은 "아니오"다. 그러면 그대로 둔다
4. "예"인 항목만 `04-functional-spec.md`에 F-번호를 받고 올라간다
