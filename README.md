# NIGHTSHIFT

한국 심야 편의점에서 점장이 남긴 **수칙**과 손님을 대조해 판정하는 규칙 기반 아날로그 호러.
문제는 수칙 중 일부가 거짓말이라는 것이다.

| | |
|---|---|
| 엔진 | Godot 4.x / GDScript |
| 플랫폼 | Steam (Windows, Proton 호환) |
| 개발 | 1인 + Claude Code |
| 목표 출시 | 2027년 4~5월 |

---

## 실행

Godot 4.4 기준. 저장소를 처음 받았다면 전역 클래스 등록을 위해 임포트를 한 번 돌린다.

```bash
# 최초 1회 — .godot/ 캐시와 class_name 전역 등록 생성
godot --headless --editor --quit

# 테스트 (F-01 공정성 불변식 4개 포함)
godot --headless --script res://tests/run_tests.gd

# 밤 하나를 헤드리스로 끝까지 돌려 대본 출력
godot --headless --script res://tools/playthrough.gd

# 화면 정보만으로 게임이 풀리는지 감사 (모순 탐지 · 솔버 · 전수 탐색)
godot --headless --script res://tools/solver_audit.gd

# 화면 렌더 확인 (가상 디스플레이)
xvfb-run -a godot --script res://tools/screenshot.gd -- --out=/tmp/s.png
xvfb-run -a godot --script res://tools/shoot_states.gd -- --out=/tmp/r.png --verdict=refuse
xvfb-run -a godot --script res://tools/shoot_states.gd -- --out=/tmp/n3.png --night=3 --locale=ko
xvfb-run -a godot --script res://tools/screenshot.gd -- --scene=res://main/title_screen.tscn --out=/tmp/t.png --press=200 --frames=280

# 실제 플레이 (한국어) — 제목 화면부터
godot

# 영어로 플레이
godot -- --locale=en

# 부스 모드 — 세이브를 무시하고 항상 첫 밤부터
godot -- --booth
```

Claude Code는 루트의 **`CLAUDE.md`를 자동으로 읽는다.** 이 파일이 프로젝트 헌법이다.

세션 시작 시:
```
docs/05-prioritization.md에서 현재 마일스톤의 다음 P0를 확인하고 시작하자.
구현 전에 계획을 3~5줄로 설명해줘.
```

## 현재 상태 — M3 (1/2) 밤 3까지 플레이 가능

**밤 1~3을 끝까지 플레이할 수 있다.** POS · CCTV · 클립보드 · 손님 · 판정 · 3초 리플레이 ·
사망 연출 3종 · 인내 압박 · 자동저장까지 동작한다. 셰이더 4종(crt · grain · paper · cctv), 절차 생성 효과음과
환경음이 붙었고, 에셋 파일은 여전히 0개다.

밤 3에서 **전환**이 처음 나온다 — 어제 맞던 둘째 수칙이 오늘 틀린다.
그 줄은 그날부터 남의 필체로 읽히고, 덧댄 새 종이가 되고, `✎` 표식이 붙는다.
**바뀌었다는 게 화면에 안 보이면 그건 퍼즐이 아니라 속임수다.**

> 🔴 **M0 게이트(5명 플레이테스트)는 아직 통과하지 않았다.** 건너뛰고 M1에 착수했다.
> H1(거짓 수칙이 재미인가)이 나중에 죽으면 M1의 UI·셰이더·사운드가 매몰비용이 된다.

| | |
|---|---|
| 테스트 | 1,997개 검사 통과 |
| 수칙 | 7개 (참 3 / 거짓 3 / 전환 1) |
| 손님 | 22명 |
| 밤 | 3박 |
| 언어 | 한국어 · 영어 (키 일치를 테스트가 강제) |
| 에셋 파일 | **0개** — 아트는 전부 코드 |
| `.tscn` | 노드 1개씩. 레이아웃은 전부 GDScript |
| 코드 | `systems/` 는 노드 비의존 — 헤드리스로 전부 검증 가능 |

### 플레이테스트 진행법

```bash
godot -- --tester=A1
```

밤이 끝나면 판정 로그가 자동 저장되고 화면에 경로가 뜬다.
손님별 판정 소요 시간, 정오답, 함정 여부, 재시작 횟수가 들어 있다.

기록지: **[docs/research/playtest-template.md](docs/research/playtest-template.md)**
테스터 1명당 복사해서 채운다. **아무것도 설명하지 않는 것**이 절대 규칙이다.

5명 기준 `data/balance.json`의 `grace_on_first_trap`을 **켬 3명 / 끔 2명**으로 나눈다.
첫 함정에서 죽이느냐 봐주느냐가 H1의 성패를 가를 가능성이 높다.

> 지금 플레이테스트를 하면 M0 텍스트 빌드가 아니라 **M2 빌드**로 하게 된다.
> 오히려 대표성은 더 높지만, H1이 죽으면 M1·M2의 UI·셰이더·사운드가 매몰비용이 된다.

## 이 프로젝트의 세 가지 원칙

**1. 아트는 전부 코드다.**
스프라이트·3D 모델·손그림 텍스처가 0개다. 화면의 모든 것은 셰이더 · 벡터 도형 · 타이포그래피 · 파티클로 만든다. 이건 예산 부족에 대한 타협이 아니라 **의도된 아트 디렉션**이다. Balatro가 그렇게 팔렸다.

**2. 주스가 그래픽이다.**
싸게 만든 게임이 유료급으로 보이는 이유는 그림이 아니라 반응성이다. 트윈, 히트스톱, 스크린셰이크, 셰이더 반응, 사운드. 기능이 "동작한다"는 완료가 아니다.

**3. 검증 전에 예쁘게 만들지 않는다.**
M0에서 코어 훅(거짓 수칙)이 재밌는지 텍스트만으로 검증한다. 여기서 실패하면 되돌린다. 예쁘게 만든 뒤에는 못 되돌린다.
